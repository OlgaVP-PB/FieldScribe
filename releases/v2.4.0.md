# FieldScribe v2.4.0 - Your data, kept safe

This release responds to a fair critique from Arnold Kochari: relying on the
browser's local storage alone is not a safe home for data people have spent time
collecting. Browser storage can be cleared by the user, evicted by the browser
under pressure, or (on iOS) removed automatically after a period of disuse. If we
tell someone their work is "saved", it should be safe to come back to.

FieldScribe stays deliberately backendless - no login, no server, works with no
signal - so the answer is not a database, but making the durable copy easy,
obvious and honest.

## What is new

**Back up all data / Restore.** On the home screen, one tap downloads a single
JSON file containing every record. That file is the durable, user-controlled
copy: keep it, email it to yourself, or use it to move data to another phone or
computer. Restore reads a backup back in and merges it, de-duplicated by a
per-record id, so re-importing the same file never creates duplicates.

**Persistent storage.** On start-up the app asks the browser to keep its data
(`navigator.storage.persist()`), which resists automatic eviction, including
iOS's roughly 7-day clear-out of unused sites. Well supported on Android/Chrome;
granted to installed home-screen apps on iOS.

**An honest nudge.** The home screen now shows how many records still live only
on this device and reminds you to back up or export. Exporting any manifest also
counts, and clears the nudge.

**Wording.** Messaging no longer implies a permanence the browser cannot
guarantee: data is stored on this device until you export or back up.

## The honest limit

Without a backend there is no central, guaranteed copy - that is the trade for a
low-threshold, no-login, offline tool. These changes make the local data far more
robust and give every user an easy durable file. If SciLifeLab later wants
server-grade durability (a central store people can always recover from), that is
a separate decision with its own auth, privacy (GDPR) and hosting implications,
worth taking on its own merits rather than as a quick patch.

## Also fixed

The Serve `Dockerfile` now ships the PWA files (`sw.js`, `manifest.webmanifest`,
`assets/`) alongside `index.html`, so install and offline work when the app is
hosted on SciLifeLab Serve.
