# FieldScribe v2.2.0 - Installable, offline-first (PWA)

v2.2.0 turns FieldScribe into a Progressive Web App: an installable, app-like
icon on the phone that opens and runs even with no signal in the field.

## What changed for users

Add FieldScribe to your home screen and it behaves like a normal app: its own
icon, a full-screen launch with no browser bars, and offline operation. The
first time you open it with a connection, it quietly saves a copy of itself to
the phone, so after that it launches and works with no signal. Records you enter
were already stored on the device; now the app itself is stored too.

## What was added under the hood

- **`manifest.webmanifest`** - app name, SciLifeLab-teal theme, standalone
  display mode, and icon set. This is what upgrades "Add to Home Screen" from a
  bookmark to a branded, full-screen app.
- **`sw.js` (service worker)** - a small background script that caches the app
  shell and serves it offline. It is version-aware: the cache is named after the
  release version, so publishing a new version automatically discards the old
  cached copy instead of leaving anyone stuck on a stale one.
  - App document (`index.html`): **network-first**, so online users always get
    the latest; falls back to cache when offline.
  - Icons, manifest, and whitelisted font/CDN hosts: **cache-first**.
  - Data lookups (ENA taxonomy, GBIF): **network-only**, never cached, so they
    are never served stale.
- **App icons** in `assets/`: 192, 512, a maskable 512 (for Android adaptive
  icons), and a 180 Apple touch icon. Teal tile with a white location pin.
- **Install metadata** in `index.html`: `theme-color`, `apple-touch-icon`, and
  the apple/mobile web-app meta tags.

## Keeping it correct on future releases

The service worker's `VERSION` must stay equal to `APP_VERSION` in `index.html`.
Bumping both on each release is what makes returning users pick up the new
version rather than a cached old one.

## Notes

The app is still a single `index.html` plus these small companion files; no build
step, no backend. Served over HTTPS (GitHub Pages, SciLifeLab Serve), which the
service worker requires.
