# FieldScribe v2.0.0 — Modular, ENA-native (roadmap)

> Status: **planned / in progress.** This note doubles as the design brief for
> the v2.0.0 line. It will become the GitHub Release body when shipped.

v2.0.0 turns FieldScribe from a single flat form into a **modular tool that
grows with the user** — simple in the field, but able to feed the full ERGA /
DToL sample manifest without anyone having to wrestle a 88-column spreadsheet or
read a 35-page SOP.

## Why this is a major version
The CSV export moves to **canonical ENA / ERGA column names and controlled
vocabularies**. Field CSVs then merge into the manifest by simply stacking rows
and joining on `COLLECTOR_SAMPLE_ID` — no manual re-mapping. Because the output
schema changes, this is a breaking change and therefore a MAJOR bump.

## The big ideas

### 1. One tool, opt-in complexity
ENA is the universal endpoint; the ERGA manifest is a broker template that feeds
ENA via COPO. So FieldScribe keeps a **lean, universal core** and exposes ERGA
depth only when the user asks for it. No separate "pro" app to maintain.

### 2. Pick your path on open
Instead of one form for everything, the user chooses a workflow, and only its
relevant fields ever appear:

- **Single specimen** — reference genome, RNA-seq (differential expression).
  Full manifest, voucherable. *(First path delivered.)*
- **eDNA / environmental** — field-only fields that vanish once you leave the
  site: filter type, pore size, volume filtered, preservation buffer.
- **Pooled / population** — many individuals, one sample; lighter ENA-checklist
  route, no tube split, no individual voucher. *(Scoped for a later release.)*

### 3. Specimen → tube model (single-specimen path)
Enter specimen-level metadata **once** (taxonomy, GPS, date, collector, habitat,
sex, life stage, photo). Then add tubes:

- **(i) one specimen per tube**, or **(ii) one specimen split across several
  tubes** (e.g. a fish divided into 15 barcoded tubes — done in the field).
- Each tube records only: **tube ID** (scan/enter — the tracking anchor),
  **collector sample ID** (auto base + suffix, editable), **organism part**, and
  **intended application** (genome / Hi-C / RNA / population).
- On export, one specimen fans out into N correct manifest rows: the shared
  block copied down, the per-tube fields varying.

The tube is the universal tracking unit — its link back to its one specimen
holds no matter which application it is destined for.

### 4. Modules filled by different people, at different times
Collection → preservation → wet lab → vouchering → sequencing become stages
attached to the same keyed record. A collector fills the field stage; a lab
engineer adds preservation/extraction later; a collection manager adds
vouchering weeks later. Unknown-yet fields default to `NOT_PROVIDED` (and can be
completed in COPO downstream), exactly as the SOP allows.

**Vouchering and biobanking apply to reference-genome material only.**

### 5. The SOP, built into the UI
Researchers don't read SOPs — so the app embeds them: inline one-line help,
controlled-vocabulary dropdowns, conditional fields (transect coordinates only
if "transect"; original-location block only if from a zoo/garden/culture), and
smart defaults. The point is that the field count *feels* small because you only
ever see the handful of fields that apply to you right now.

## Field-stage minimal set (don't scare the collector)
Only what is physically unrecoverable after leaving the site, plus cheap in-hand
observations — roughly 12–15 fields, most auto-filled or one tap:
collector sample ID; GPS (+accuracy); date/time; location; habitat;
depth/elevation; collection method; collector (+affiliation/ORCID); a photo;
plus rough taxonomy, life stage, sex, organism part. Everything that needs a
database (e.g. NCBI TaxID), a decision, or another person is deferred to a later
module.

## Schema basis & version delta
Built against **ERGA Sample Manifest v2.5.1** (91 columns), extracted to
`schema/manifest-2.5.1.json` and embedded inline so the app validates offline.
Delta from the v2.4.2 we started on:
- **+3 columns** (carried from v2.5): `ETHICS_PERMITS_FILENAME`,
  `SAMPLING_PERMITS_FILENAME`, `NAGOYA_PERMITS_FILENAME` — formalise the SOP's
  permit-PDF uploads. (Deferred to a later module; exported blank for now.)
- **Richer tissue vocabularies** for `ORGANISM_PART` / `TISSUE_FOR_BARCODING` /
  `TISSUE_FOR_BIOBANKING` (muscle, fin, skin, gonad, full plant/fungi/culture
  terms) — now 73 defined organism-part terms, all wired into the dropdowns.
- **`PURPOSE_OF_SPECIMEN` gained `RESEQUENCING`** (covers population/resequencing
  intent) and `NOT_PROVIDED`.

## Open question carried into build
`PURPOSE_OF_SPECIMEN` still has **no Hi-C term**. Handled in-app by offering a
UI-only "Hi-C" choice that exports as `REFERENCE_GENOME` with "Hi-C" appended to
`OTHER_INFORMATION`. Worth proposing Hi-C as a formal term to ERGA (Felix Shaw).
